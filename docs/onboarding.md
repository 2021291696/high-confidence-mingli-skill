# Onboarding — 首次建档流程

> 触发：SKILL.md 启动检查发现 `~/.claude/fortune-telling/chart.md` 不存在。
> 目标：生成 chart.md（命盘数据）+ memory.md（运行时记忆），之后进入正常四模式路由。
> 原则：**先建档，后算命**——数据未就绪前不做任何运势判断。
> **三盘由 `scripts/` 内置确定性引擎排出**（八字 Meeus 定气 / 紫微 iztro / 七政 自研恒星制），
> 干支、安星、躔度一律以脚本输出为准，禁止口算覆盖。App 导入只是引擎不可用时的备选。

## 第 0 步：欢迎与隐私说明

向用户说明三件事：

1. 本 skill 是「三盘互译」命理引擎：八字 + 紫微斗数 + 七政四余互相验证，不给空泛断语
2. 三盘由内置确定性引擎直接排出，只需要出生信息；每个引擎都带回归测试与对拍锚点
3. **所有数据只存在本地** `~/.claude/fortune-telling/`，不上传、不联网、不与任何账户绑定

## 第 1 步：采集基础信息

依次询问（一次问完，别挤牙膏）：

| 字段 | 必需性 | 说明 |
|------|--------|------|
| 称呼 | 必需 | 昵称即可 |
| 性别 | 必需 | 大运顺逆 + 十神感情映射（男看财/女看官）必需 |
| 公历出生日期 | 必需 | YYYY-MM-DD；只知道农历的用户，八字引擎支持 `--lunar` 直排 |
| 出生时间 | 必需 | 精确到分钟最佳；不知道 → 见下方「时间未知处理」 |
| 出生地点 | 必需 | 城市级，换算经纬度（引擎需要 lat/lon 定命度与昼夜生） |

**时间未知处理**：只知大概时辰 → 按该时辰中点建档，chart.md 时柱标注「置信度：时辰估计」；完全不知道 → 三柱建档（年月日），时柱留空，所有涉及时柱的判断（子女宫、晚年运、部分格局判定）标注「时柱缺失」。紫微必须时辰（命宫定不了），七政命度也依赖时刻精度。

## 第 2 步：一键排盘（主线）

跑建档总控，三盘一次生成：

```bash
cd <本 skill 目录>
python3 scripts/build_chart.py --solar 1990-05-15 --hour 14:00 --sex 男 \
    --lat 31.23 --lon 121.47 --place 上海 --name 某某
```

总控内部依次执行：

1. **八字**（`scripts/pai_pan_bazi.py`）：定气定朔排四柱、十神、藏干、大运（起运岁数=距节天数÷3，脚本算）、神煞、农历；`--lunar` 可直排农历生日
2. **七政**（`scripts/pai_pan_qizheng.py`）：恒星制十一曜躔度、命度（真升点，含均时差校正）、立命宫（果老安命法）、昼夜生（日出日落脚本算）、恩用难仇；副产品输出精确均时差
3. **紫微**（`scripts/pai_pan_ziwei/`，首次需 `npm install`）：iztro 排十二宫、生年四化、大限、格局

**引擎不可用降级**：无 node → 紫微节自动标注缺失并按缺盘降级运行（备选：从文墨天机/测测等 App 复制十二宫信息粘贴）；无 python3 → 整体退回 SKILL.md §6/§7 口算降级路径（输出强制标注「口算降级」）。

## 第 3 步：真太阳时校正

`build_chart.py` 已自动完成：经度校正 + 均时差（七政引擎按 Meeus 精确计算，非估算）。
校正如跨越时辰边界（如 21:05 → 20:48，亥时跌入戌时）→ 必须告知用户并确认用哪个时辰。
只有大概时辰的用户，用真太阳时复核一次时辰归属。

## 第 4 步：排盘结果确认

向用户展示 chart.md 摘要（四柱 + 格局 + 十二宫 + 命度立命宫 + 缺失的盘），请确认。
用户手上有排盘 App 的可当场核对——三引擎输出与主流排盘工具应在容差内一致
（八字/紫微一致；七政注意本仓为恒星制口径，与回归制软件相差约 24° 属学派差异，见引擎文件头口径声明）。

## 第 5 步：判读字段补全（agent 分工）

chart.md 中 `<!-- agent: -->` 标记的判读字段由 agent 依**脚本输出**判定（禁止改动脚本数字）：

- 十神链、核心冲合（依四柱表）
- 格局/调候/日主强弱（依月令透干，附一句推理依据）
- 解释器种子 → 写入 memory.md「运行时画像」（按 SKILL.md §3 推导规则）

## 第 6 步：写盘并确认

1. 创建目录 `~/.claude/fortune-telling/`（不存在则建，含 `memory-archive/`）
2. 将 build_chart.py 输出 + 第 5 步判读字段合成为 `chart.md`
3. 按 `templates/memory.template.md` 填种子值 → 写 `memory.md`
4. 向用户展示确认 → 「建档完成，可以问运势、推演问题、或聊聊命理概念」

## 维护操作（非首次）

| 用户说 | 操作 |
|--------|------|
| "重新建档 / 重置命盘" | 备份现有 chart.md 到 memory-archive/ 后重走本流程 |
| "修改出生信息" | 确认后重跑 build_chart.py，重新推导受影响部分（时柱变→格局/解释器重推） |
| "补充紫微/七政数据" | 引擎时代三盘默认齐全；仅当紫微引擎不可用时才按旧流程从 App 导入 |
